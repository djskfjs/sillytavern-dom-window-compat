# 桌面隔离测试记录

版本：0.4.3-compat.1  
日期：2026-11-04  
环境：Windows 上的 Chrome 无头浏览器，390 × 844 竖屏尺寸。  
数据：合成聊天、模拟酒馆接口与酒馆助手；不使用真实聊天、密钥或账号。

共完成 10 项检查。第 1 项复现原版缺陷，其余检查验证修正版行为。

| 检查 | 结果 |
| --- | --- |
| 原版 0.4.2：原始消息无 HTML 标记，显示后生成 HTML 前端 | 缺陷复现，窗口重建后没有前端 iframe |
| 返回 jQuery 的现代接口：上翻、回底、关闭恢复 | 通过，聊天数据不变 |
| 不返回元素的旧接口：上翻、回底、关闭恢复 | 通过，聊天数据不变 |
| 2601 层快速上下滚动、静止检查 | 通过，无重复楼层和静止后的反复渲染 |
| 补渲染过程中切换聊天 | 通过，旧任务不生成其他聊天的前端 |
| 追加正常新消息 | 通过，增量追加，无整窗重建 |
| 单个前端刷新失败 | 通过，继续处理其他楼层，失败楼层解除等待提示 |
| 窗口挂载临时异常 | 通过，关闭窗口模式并恢复普通展示 |
| 原版旧开关及重复加载 | 通过，不继承旧版自动开启状态，不覆盖运行实例 |
| 停用及重新加载 | 通过，接口和面板被清理，重新加载后可正常开启 |

2601 层这一轮：插件补渲染最大并发为 1；丢弃 336 个失效任务；返回后保留 14 个楼层展示。实际挂载数受阅读位置和缓冲余量影响，不是严格等于预加载数。

队列串行不等于所有 iframe 只运行一个：已经恢复的前端仍可同时运行。

自动检查还确认：聊天 JSON 不变、消息 ID 不重复且顺序正确、最后一层标记正确、关闭后恢复初始渲染数、恢复队列不直接调用聊天保存接口。

本记录不能证明真实 Safari 不黑屏或不重载。未覆盖真实 98 MB 聊天、所有第三方前端、真实酒馆助手长期运行及 iOS 系统回收。真机步骤见 `IOS-验收清单.md`，完整机器记录见 `TEST-RESULTS.json`。
