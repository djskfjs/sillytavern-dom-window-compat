# 本地预览：重载记录留存

这是 2026-11-08 本地验证阶段的记录，当时保留正式版本号 `0.4.3-compat.6`，构建为 `本地预览-20261108-重载记录留存`。定稿后统一发布为 `0.4.3-compat.7`，当前安装方法见 [发布说明](重载记录留存-发布说明-20261108.md)，下文的预览构建信息供回溯验证使用。

## 为什么重载后可能看起来一样

旧诊断主要导出当页状态。页面重新打开时，楼层数、iframe 数量和队列状态可能回到相同值。这些数值是状态快照，不能直接说明白屏原因。用户反馈两次信息相同，但原始报告已没有保留，因此不能断言当时是旧构建、复制了旧文本、没有实际创建新文档，还是存储记录丢失。

代码中确实存在留存缺口：上一页记录只在当前文档的内存里保留，持久存储会被新页面覆盖，再次重载后就无法从那里取得最初记录。仅测试普通刷新也不足以证明页面进程突然终止时仍可取回证据。

## 这次改动

- 每个新文档有不同页面编号；同一文档内重新启用扩展沿用原编号，不伪造一次页面重载。每次导出另有报告编号和生成时间，用于识别是否复制了同一份报告；报告编号变化本身不是重载证据。
- 会话存储保留当前页及最近 3 个历史页面；本地存储最多备份 4 个页面。多标签页写入时先读最新备份，尽量保留其他标签页的记录。
- 会话报告丢失、标签页身份仍在时，从匹配的浏览器备份恢复。身份也丢失时，备份单列为“来源未确认”，不能认作本标签页的上一页。
- 界面和报告明确说明有没有取得上次记录，显示前后编号、开始时间及上次最后记录时间。即使数量一样，也可以核对取到的是哪个页面。
- 离开标记与普通事件分开保存，避免被事件队列挤掉；从往返缓存返回时清除已过期的离开标记。

## 如何读结果

| 摘要 | 能说明什么 |
| --- | --- |
| 没有取得本标签页的上次记录 | 缺少可归属的上一页证据，不能判断上次白屏 |
| 有页面离开事件 | 收到了离开通知；不能据此排除白屏或断言正常退出 |
| 没有页面离开事件 | 可能发生中断，也可能浏览器未发送事件；不能单独认定崩溃 |
| 有本扩展刷新请求 | 本扩展记录过刷新请求，不代表所有白屏都由它造成 |
| 有来源未确认的浏览器记录 | 本地备份还在，但可能属于其他标签页，必须保留这个不确定性 |

报告保留 `previousPage`，另加 `previousPages` 和 `unlinkedBrowserPages`。历史记录里仍有预设切换前后事件、当时数量和扩展刷新标记。浏览器进程被系统终止时，扩展无法在已经终止的进程中补写日志，也不能直接读取 iOS 的系统崩溃报告。

## 验证和范围

单元及浏览器检查覆盖相同数量但不同页面、连续重载保留更早记录、会话报告丢失、标签身份丢失、多标签页、往返缓存和同页重新启用扩展。另在合成聊天中通过 Chrome DevTools 的 `Page.crash` 实际终止测试页渲染进程，再通过同一个标签页的 DevTools 会话重新加载。

进程终止前后 iframe 数量相同；恢复后取到了不同页面编号，以及没有 `pagehide` 的中断前预设事件。再加载一次，最初的页面记录仍在。**这验证的是留存链路，不是复现或解决 iPhone Safari 白屏原因。** 详细结果和文件哈希见 [测试记录](重载记录留存-测试结果-20261108.json)。

## 安装

1. 备份现有 DOM Window 扩展目录，将本地预览 ZIP 中的 `sillytavern_dom_window` 文件覆盖到原兼容版的实际安装目录，然后刷新一次，不需要重启服务器。
2. 确认底部是“本地预览 · 2026-11-08 · 重载记录留存”，报告为 `format: 3`。正式版本号仍是 `0.4.3-compat.6`，不能仅凭它判断构建是否更新。
3. 若以后再次白屏，等页面恢复后导出诊断。摘要会直接说明是否取得上次记录；无需依靠 iframe 数量有没有变化来猜测。

浏览器清除会话和本地存储、两种存储都拒绝写入，或故障发生在扩展执行前，仍可能没有可用记录；界面会说明没有取得，不会当作诊断成功。之前已经丢失的原报告无法由这次更新补回。
