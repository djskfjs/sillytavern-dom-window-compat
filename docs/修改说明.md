# 修改说明

## 已确认的线索

上游 0.4.2 只在原始消息含 `PlaceHolder`、`<html>`、`<head>` 或 `<body>` 时补发前端渲染。正常显示时由正则或格式化生成的前端可能被漏掉，重新挂载后只剩代码。

另一个版本差异是旧酒馆的 `addOneMessage()` 会创建元素但不返回元素；1.18.0 已返回 jQuery 对象。兼容版同时保留对这两类接口的处理。

以上不等于已经确认 iOS 黑屏或自动重载的完整原因。

## 保留与修改

保留上游的视口窗口、占位、最后一层固定挂载和消息数据来源。继续使用酒馆及酒馆助手的正常渲染接口，未复制或缩短完整聊天数组。

新增 `render-queue.js`，负责显示后代码块识别、补渲染排队、过期任务检查和临时等待提示。只直接处理展示元素，不接管聊天保存、密钥或箱装备份。

快速滚动时，合并待恢复任务；回收的楼层不再继续补渲染。已经开始的酒馆助手异步调用无法强制终止，但只允许一个在执行，并在结束后复核任务是否仍有效。

如果前端内部自行发请求或修改数据，这仍属于该前端自身行为；本补丁没有接管其代码。楼层重新挂载时前端会重新初始化，临时交互状态可能重置。

## 验证与限制

自动化测试使用合成聊天与模拟接口，验证显示后代码块、旧 API、快速滚动、切换聊天、增量消息、异常恢复和重复加载。具体结果见交付的测试记录。

实际 iOS、实际酒馆助手和用户前端的长期行为必须再验证；不将模拟接口测试称为真实酒馆整合测试，也不保证修复系统回收或浏览器崩溃。
