# 0.4.3-compat.7 发布说明：诊断复制与重载记录留存

日期：2026-11-08。构建名称为“重载记录留存”，从原仓库 `djskfjs/sillytavern-dom-window-compat` 更新。上一版默认分支为 `0.4.3-compat.6`，提交 `15371935888b05e9d16e2aea937b7fa88bc35153`。

## 本次修复

此前复制失败可能没有反馈；诊断主要展示状态快照，页面再次重载还会覆盖更早的记录。现在复制成功或失败会明确提示，并提供全选文本、下载 JSON 两种备用方式。

报告会说明是否取得上次页面记录，显示前后页面编号、开始时间和最后记录时间。会话内最多保留 3 次历史页面，浏览器本地备份最多保留 4 个页面。无法确认属于当前标签页的备份单独标记，不当作已确认的上一页。每次导出还有单独的报告编号和生成时间，用于识别是否重复复制了同一份文本。

AI 预设切换前后会记录少量事件及前端数量，保留切换开头的证据；不记录预设名、聊天正文、网址或 API 密钥，不上传数据。保留原有生成期间暂停回收、后台暂停和异常时保留页面的保护。

## 验证与限制

发布文件完成单元、Chrome 通用窗口、滚动与设置、异常与后台、生成保护和诊断检查，并在桌面 WebKit 检查复制、下载、记录恢复及卸载。最终文件校验值和检查明细见 [发布测试结果](重载记录留存-发布测试结果-20261108.json)。

Chrome 诊断包含实际终止测试页渲染进程后，在同一个标签页重新加载。前后 iframe 数量相同，但能够区分页面编号，取回中断前的预设事件，再次加载后也保留该记录。

**这验证的是记录留存，不代表已经复现或解决 iPhone Safari 白屏的原因。** 没有离开事件只能提示可能中断，不能单独证明崩溃；没有取得上次记录时会明确说明。之前已经丢失的报告不能由此次更新补回。清除网站数据、禁止存储或故障发生在扩展执行前，仍可能没有可用记录。

## 更新方法

1. 在酒馆“管理扩展程序”中更新原 DOM Window 兼容版，然后刷新页面。
2. 确认界面版本为 `0.4.3-compat.7`，底部显示“重载记录留存”；报告应为 `format: 3`，构建为“重载记录留存”。
3. 如果以后自行白屏重载，等页面恢复后导出诊断。先看摘要有没有取得上一页记录，不依靠楼层或 iframe 数量是否相同判断。

ZIP 安装时备份原扩展目录，再用安装包中的 `sillytavern_dom_window` 文件覆盖当前兼容版的实际安装目录，不要同时启用两份扩展。无需重启服务器。
