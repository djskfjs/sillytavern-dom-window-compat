# DOM Window 兼容测试版 0.4.3-compat.1

基于 [Sntolo/sillytavern_dom_window](https://github.com/Sntolo/sillytavern_dom_window) 的 0.4.2 制作，原版基线为 `deb062cbfb729198c8c70e99cfbfa43fa96f84ee`。这是独立兼容修正版，不是原作者的正式发布。

本版修正旧楼层重新挂载后的前端漏渲染，并减少快速滚动时同时进行的补渲染任务。保留原版按阅读位置回收楼层的方式。

**iOS 黑屏与自动重载是否改善仍需要真机验证。它不能阻止 iOS 强制回收页面或保证浏览器不崩溃。**

## 主要修改

- 检查显示处理后的代码块，覆盖由正则或格式化生成、原始消息不含 HTML 标记的前端；实际是否可渲染仍由酒馆助手判断。
- 补渲染逐个执行，滚动停止后再处理；优先处理正在阅读的范围和最后一层。
- 已回收楼层、已切换聊天、已变更候选或内容的旧任务不会继续启动。
- 将目标楼层元素传给酒馆助手，并在完成后复核高度和阅读位置。
- 等待补渲染时显示“正在恢复前端界面”，避免把临时代码展示误认为最终结果。
- 兼容旧酒馆创建楼层但不返回元素的接口。
- 使用独立开关与预加载设置，默认关闭，不自动继承原版的开启状态。

## 云酒馆：通过 GitHub 地址安装

安装地址：

```text
https://github.com/djskfjs/sillytavern-dom-window-compat
```

1. 等当前回复结束，确认聊天已保存。
2. 在「管理扩展程序」中停用原版 **DOM Window 扩展本体**，刷新一次。仅关闭原版的“进入聊天时自动开启”还不够，原版脚本仍会加载。
3. 在云酒馆的「扩展程序 → 安装扩展程序」里粘贴上面的仓库地址，完成安装。
4. 确认保存后刷新网页，检查扩展名是“DOM Window 兼容测试版”、版本是 `0.4.3-compat.1`。
5. 兼容版默认关闭，从预加载 5 层开始手动开启，按真机验收清单测试上翻前端与快速滚动。

酒馆服务器会从 GitHub 下载代码，手机和电脑都可访问云酒馆使用。无需把 D 盘目录复制到每台设备，也无需 npm 安装或重启 VPS。

## 手动 ZIP 安装或替换

1. 等当前回复结束，确认聊天已保存，保留箱装备份。
2. 先在原版 DOM Window 中取消“进入聊天时自动开启”。
3. 把旧 DOM Window 文件夹移到**第三方扩展目录之外**备份，避免两份脚本同时加载。
4. 解压测试安装包，把里面的 `sillytavern_dom_window` 文件夹放到酒馆第三方扩展目录。例如：

   ```text
   SillyTavern/public/scripts/extensions/third-party/sillytavern_dom_window
   ```

   如果酒馆将扩展装在用户目录，则使用原版所在的 `data/<用户名>/extensions/` 路径。沿用实际安装位置即可。

5. 确认目录里有 `index.js`、`render-queue.js`、`manifest.json`、`settings.html` 和 `style.css`，不要只替换 `index.js`。
6. 刷新一次酒馆网页，在扩展设置中确认显示“DOM Window 兼容测试版”。
7. 从默认预加载 **5 层**开始，手动勾选“进入聊天时自动开启”，再慢慢上翻验证。该开关保存在当前浏览器，不同步其他设备。

不需要运行服务器插件，也不需要 npm 安装运行依赖或重启 VPS。测试安装包包含本版完整运行源码和原许可证。

不要同时启用原版和兼容版。可以保留已停用的旧版目录，但须先在「管理扩展程序」停用原版并刷新。兼容版发现已存在的 DOM Window 实例时会跳过重复加载；无法约束随后加载的未修改原版。

## 使用边界

- 只保留阅读位置附近及最后一层的展示。预加载数不是严格的全局楼层数量上限，视口余量也会影响实际挂载数量。
- 聊天数组仍完整，AI 上下文和聊天保存接口没有被本补丁接管。浏览器仍需要读取完整聊天数据。
- 与原版一样，开启时会临时调整酒馆的初始渲染数量，关闭时恢复本次开启前记录的值。
- 楼层里的前端会重新初始化，临时交互状态可能重置。前端自身的脚本行为仍由其作者负责。
- 远离阅读位置但尚未回收的前端可能保留为等待任务，重新滚到附近时再恢复。
- 已经开始的酒馆助手异步调用不能被强制终止；后续任务会等待它结束，并复核是否仍有效。
- 改预加载参数时，“保存”会询问是否刷新。当前回复未结束或聊天未保存时不要确认刷新。
- 更新兼容版时请使用本仓库地址，不要用上游原版代码覆盖兼容修正。
- 队列数字表示正在恢复的调用数，已经渲染好的多个前端仍可能同时运行。

## 关闭与回退

取消“进入聊天时自动开启”会关闭窗口模式并恢复普通展示。前端恢复是异步的，等待状态结束后再检查。

如仍有黑屏、反复闪烁或长期只剩代码，先关闭兼容版，确认聊天已保存后重新进入。需要回退时，移出兼容版，放回备份的原版文件夹；不要在两个版本同时存在时刷新。

纯展示故障通常不需要反复恢复聊天备份。先确认真正丢失的是聊天内容还是没有渲染出来的界面。

## 测试与开发

测试记录见 `docs/测试记录.md` 和 `docs/TEST-RESULTS.json`；修改说明见 `docs/修改说明.md`。真实手机步骤见 `docs/IOS-验收清单.md`。

自动化测试使用合成聊天、模拟酒馆接口和模拟酒馆助手，不能替代真实酒馆整合测试或 Safari 真机验证。

开发测试可以安装 `package.json` 中的 Playwright 开发依赖后运行 `npm test`。使用系统 Chrome，或通过环境变量 `DOM_WINDOW_BROWSER` 指定已有的 Chromium 可执行文件；`DOM_WINDOW_BASELINE` 指向原版完整源码目录，`DOM_WINDOW_TEST_OUTPUT` 指定测试记录输出目录。测试不连接真实酒馆，不使用聊天正文或密钥。
