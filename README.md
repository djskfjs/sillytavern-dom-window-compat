# DOM Window 兼容测试版 0.4.3-compat.4

基于 [Sntolo/sillytavern_dom_window](https://github.com/Sntolo/sillytavern_dom_window) 的独立修改版，保留原版权与许可证。上游基线：`deb062cbfb729198c8c70e99cfbfa43fa96f84ee`。

设置阅读窗口层数并开启即可。窗口跟随上下阅读位置移动，移出窗口的助手前端会回收；重叠楼层继续复用。设为 10 层时，阅读历史记录最多保留连续 10 层和最后一层。

## 安装与使用

在酒馆的「扩展程序 → 安装扩展程序」填入：

```text
https://github.com/djskfjs/sillytavern-dom-window-compat
```

已有兼容版则在「管理扩展程序」更新，刷新页面确认版本为 `0.4.3-compat.4`。原版和兼容版只启用一个。

1. 在 DOM Window 设置阅读窗口层数，例如 10，点击保存。
2. 勾选「启用窗口」。若助手设置需要适配，扩展会保存原值、自动配置并刷新一次，然后开启窗口。
3. 以后修改层数，点击保存立即应用，保留当前阅读位置，不需要刷新页面或重启服务器。
4. 关闭窗口时，扩展会还原它修改的助手设置；确实有设置需要还原时会自动刷新一次。原本就符合条件则开关都无需为配置刷新。

当前已适配 **酒馆助手 4.12.0**。检测到其他版本时会明确显示版本号，暂不使用未经核对的前端回收机制。未安装助手可以使用文字窗口。SillyTavern 需为 1.14 或以上。

## 自动适配的范围

扩展只按需调整助手的渲染深度和流式渲染：深度 0 让助手渲染窗口内已挂载的楼层，实际楼层数量由 DOM Window 控制；流式渲染临时关闭。原值随当前账号设置保存，并标记本浏览器，避免另一个浏览器误还原。关闭后，只恢复仍是适配值的字段，保留用户后来手动修改的其他值。

助手的保存设置和实际生效设置是不同副本，所以首次适配或还原需要刷新一次。只有确认设置保存成功才刷新，保存失败会回退并给出说明。生成回复过程中不进行会刷新页面的配置。层数调整在当前页面直接完成。

## 行为与限制

- 不修改聊天数组、AI 上下文、消息 ID 或聊天保存内容。完整聊天数据仍留在浏览器中。
- 前端移出窗口后卸载，重新进入时会初始化，尚未保存的前端交互状态可能重置。
- 初次开启复用已显示的楼层；回收期间保留高度，避免滚动位置突然变化。持续滑动不会无限推迟前端恢复。
- 一层可以包含多个 iframe，窗口层数不能当作内存上限。很短的楼层不足以填满屏幕时可适当增加层数。
- 恢复调用超过 15 秒未响应时，窗口会停止并提示刷新，不叠加第二个恢复调用。
- 这是兼容测试版。电脑测试不能证明 iPhone Chrome 的黑屏或自动重载已经完全解决，手机仍需按 [验收清单](docs/IOS-验收清单.md) 验证。

## 开发与打包

`npm test` 运行设置适配测试、通用浏览器回归与滚动专项测试。浏览器测试使用系统 Chrome 和合成聊天，不使用真实聊天或密钥。环境变量：`DOM_WINDOW_BROWSER` 指定 Chromium；`DOM_WINDOW_BASELINE` 指向上游源码；`DOM_WINDOW_PREVIOUS` 指向 compat.1 源码；`DOM_WINDOW_TEST_OUTPUT` 指定记录目录；`DOM_WINDOW_TEST_SOURCE` 可用于滚动测试对比其他版本。

ZIP 安装时将 `sillytavern_dom_window` 放入实际第三方扩展目录。运行文件必须包含 `index.js`、`render-queue.js`、`moving-window.js`、`helper-lifecycle.js`、`helper-setup.js`、`settings.html`、`style.css` 和 `manifest.json`。

详见 [更新日志](CHANGELOG.md)、[测试记录](docs/测试记录.md) 和 [助手回收说明](docs/兼容回收说明.md)。
